# 星遇部署说明

示例安装包：**starlit-1.0.0-rc.3-docker.tar.gz**。使用其他版本或源码包时，请下载对应 Release 的安装说明；打包工具会生成匹配版本和包类型的 `INSTALLATION.md`。

从 [GitHub Releases](https://github.com/coency/web-3d-lottery/releases) 选择一种部署包，并下载同名 `.sha256` 文件。源码包对应 `SOURCE_INSTALLATION.md`，镜像包对应 `DOCKER_INSTALLATION.md`；不要把 GitHub 自动提供的 Source code 当作部署包。

- 镜像包包含应用、网站入口和 PostgreSQL 镜像，服务器直接导入。
- 源码包较小，服务器需要联网下载基础镜像及 npm 依赖，再构建应用。
- 两种包都会自动安装缺少的 Docker Engine 和 Compose；无需预装 Node.js、PostgreSQL、WSL 或 Docker Desktop。

第一次安装和更新已有网站，都先完成第 1、2 部分。之后，首次安装看第 3 部分，升级看第 4 部分，二选一。

**每次只执行一个命令框。命令完成、没有报错后，再继续下一步；报错就停下。**

## 1. 上传文件

使用 FTP 工具上传，推荐 [FileZilla Client](https://filezilla-project.org/download.php?type=client)。

打开 FileZilla，点击「文件 → 站点管理器 → 新站点」，填写：

| 项目 | 填写内容 |
| --- | --- |
| 协议 | SFTP |
| 主机 | 你的服务器公网 IP |
| 端口 | 22；服务商另有指定时使用指定端口 |
| 登录类型 | 正常 |
| 用户 | root |
| 密码 | 你的服务器密码 |

点击「连接」。首次出现主机密钥提示时，核对服务商提供的指纹后确认。

连接成功后：

1. 在右侧「远程站点」栏输入 `/root/`，按回车。
2. 在左侧找到下面两个文件，依次拖到右侧。
3. 等待上传完成，确认底部没有失败的传输。

需要上传的文件：

- `starlit-1.0.0-rc.3-docker.tar.gz`
- `starlit-1.0.0-rc.3-docker.tar.gz.sha256`

保留原文件名，不需要在电脑上解压。

## 2. 在服务器上解压

登录购买服务器的网站，打开这台服务器的「远程连接 / 终端」，以 root 登录。

**以下命令都在服务器终端执行，不在 FileZilla 中执行。**

### ① 进入上传位置

```bash
cd /root
```

### ② 检查文件完整性

```bash
sha256sum -c starlit-1.0.0-rc.3-docker.tar.gz.sha256
```

看到 **OK** 或「成功」才继续。

### ③ 创建默认安装位置

```bash
mkdir -p /opt/starlit
```

### ④ 解压

如果服务器已经存在 `/opt/starlit/starlit-1.0.0-rc.3-docker`，先停止操作，不要覆盖已有目录。

```bash
tar -xzf /root/starlit-1.0.0-rc.3-docker.tar.gz -C /opt/starlit
```

等待命令结束。没有报错、重新出现命令提示符，就可以继续。

**现在选择：没有安装过，做第 3 部分；已经安装过，跳到第 4 部分。**

## 3. 首次安装

安装前需满足：Ubuntu 22.04 / 24.04 或 Debian 12 / 13，x86_64 架构；使用 root 账号；域名已解析到服务器公网 IP；TCP 80、443 端口已放行。若设置了 AAAA 记录，IPv6 也须可达。已有服务占用 80/443 端口时，安装会停止。无需提前手动安装 Docker。安装脚本会安装 Docker 和 Compose。镜像包直接导入镜像；源码包还需下载依赖和构建项目。首次安装 Docker 仍需要联网，域名证书和微信接口也需要联网。

### ① 进入新包目录

```bash
cd /opt/starlit/starlit-1.0.0-rc.3-docker
```

### ② 启动安装

```bash
bash install.sh
```

程序先检查系统和端口。根据屏幕提示填写信息，脚本会自动安装缺少的 Docker 环境、导入或构建镜像并启动服务。

### ③ 按屏幕提示填写

| 提示 | 填什么 |
| --- | --- |
| 网站域名 | 你的网站域名，不带 https://、端口或路径 |
| 登录账号 | 自己设置的网站账号 |
| 设置密码 | 自己设置的网站密码 |
| 再次输入密码 | 再输入一次相同密码 |

每次填写后按回车。密码输入时不显示字符，是正常现象。

保持窗口开启，等待出现 **「网站已启动」**。然后在浏览器打开网站，用刚设置的账号和密码登录。

**首次安装完成，不需要再执行升级步骤。**

## 4. 升级已有网站

旧版安装目录以 `-images` 结尾也可以继续使用，不要手动改名或搬动正在运行的目录。新版下载包和解压目录统一以 `-docker` 命名，升级仍在原网站目录执行。

请避开活动进行期间。升级会自动备份，保留服务器上的账号、活动、名单、图片和配置。

### ① 进入原网站目录

下面的命令适用于按默认方式安装在 `/opt/starlit/` 下的单个网站，会自动定位原目录，星号不用修改：

```bash
cd /opt/starlit/*/config/..
```

**这一条没有报错，才能继续。**若提示找不到目录或参数过多，停止并提供报错截图，不要执行下一条。

### ② 更新原网站的维护脚本

这一步让旧源码版的维护脚本也能识别镜像包，并在本次升级成功后自动清理，不需要另下载补丁。

先保留原脚本：

```bash
cp -p starlit.sh starlit.sh.before-upgrade
```

再使用新包中的脚本：

```bash
install -m0700 /opt/starlit/starlit-1.0.0-rc.3-docker/starlit.sh ./starlit.sh
```

### ③ 启动升级

```bash
bash starlit.sh upgrade /opt/starlit/starlit-1.0.0-rc.3-docker
```

保持窗口开启，等待出现 **「升级完成」**。通过清理检查后，会自动删除 `/root/` 下本次上传的压缩包及校验文件，以及本次新解压目录；原网站目录、配置、业务数据、备份及内部版本副本保留。升级失败或检查不通过时保留相关文件。

不要执行 `install.sh`，不要删除原网站文件夹。

### ④ 刷新页面

- 电脑后台按 **Ctrl + F5** 刷新。
- 关闭旧大屏，再重新打开。
- 微信关闭旧签到页面，重新扫码。

升级完成。

## 5. 微信接入

网站启动后，进入「签到设置 → 配置服务号」，填写自己的已认证服务号信息。

1. 在微信公众号后台设置网页授权域名，下载 `MP_verify_*.txt` 原文件。
2. 在本系统的「配置服务号」弹窗上传该文件。文件会存入网站运行目录的 `data/verification/`，不是 `/root/` 或 `/opt/` 根目录。
3. 回到微信后台完成域名验证并保存，再在本系统确认已保存域名，点击「检查微信接入」。通过后显示接入已就绪。

校验文件通过网站根路径公开访问。不要把 AppSecret 或其他密钥放进这个目录。系统检查不能代替微信后台保存域名，也不代表已取得参与者授权；最后仍应使用手机微信验证一次实际签到流程。

## 6. 常用维护和备份

以下命令均在原网站运行目录执行。按默认方式只安装一个网站时，先定位目录：

```bash
cd /opt/starlit/*/config/..
```

命令报错时停止操作；不要在新解压的升级包目录执行维护。

查看运行状态：

```bash
bash starlit.sh status
```

查看近期日志：

```bash
bash starlit.sh logs
```

停止网站，保留数据：

```bash
bash starlit.sh stop
```

重新启动网站：

```bash
bash starlit.sh start
```

重置指定账号的登录密码：

```bash
bash starlit.sh reset-password
```

创建完整备份：

```bash
bash starlit.sh backup
```

`start` 会重建网站容器；备份会短暂停止网站写入，结束后尝试恢复原本运行的网站。请避开抽奖时间，不要同时执行多个维护命令。

备份位于运行目录的 `backups/`，包含数据库、上传图片、配置、微信密钥及证书。完整备份带有校验清单；含 `INCOMPLETE` 的备份不能用于恢复。应将备份另存到服务器之外并妥善保管。当前未自动配置定时备份。

### 恢复备份（仅用于全新目录）

使用与备份相同版本的部署包，在新服务器或全新目录恢复。不要先运行 `install.sh` 创建新数据库，不要覆盖现有网站。

进入该版本部署包的解压目录后，先安装所需环境：

```bash
bash engine.sh
```

然后执行恢复。下面的备份路径需要换成实际保存的完整备份目录：

```bash
bash starlit.sh restore /绝对路径/完整备份目录
```

恢复保留原域名和密钥。更换服务器后需修改域名解析、微信服务器 IP 白名单，并检查 HTTPS、登录和手机签到。恢复会拒绝覆盖已有安装；恢复失败时保留现场，不要当作已经恢复成功。

## 7. 升级后的自动清理

升级时先准备新镜像，再停止网站、备份、迁移数据库并启动新版。数据库迁移失败时网站保持停止；系统不会自动降级数据库，应使用旧版本包和升级前备份在全新目录恢复。数据库大版本升级不属于普通网站升级范围。

网站及 HTTPS 检查通过、维护脚本更新完成后，自动清理：

- `/root/` 下本次上传的部署压缩包。
- 同名 `.sha256` 文件。
- 本次升级指定的新解压目录。

源码包和镜像包均支持，按实际包类型识别；不会删除另一种类型的同版本文件。

上传包必须通过完整性检查。新解压目录必须位于运行目录之外，内容与内部版本副本一致，且不含额外数据、符号链接或挂载点。检查不通过则保留相关文件并提示；清理失败不会撤销已完成的升级。

**首次安装不会自动删除安装目录。升级后原网站运行目录继续使用，新解压目录只是本次升级的输入。**

### 运行目录中的数据

| 路径 | 内容及处理方式 |
| --- | --- |
| `config/` | 数据库密码、微信加密密钥、登录密钥和域名；必须保留 |
| `data/postgres/` | 数据库；必须保留 |
| `data/uploads/` | 上传图片、缓存及生成的头像；必须保留 |
| `data/verification/` | 微信域名校验文件；必须保留 |
| `data/caddy/`、`data/caddy-config/` | HTTPS 证书及网关状态；必须保留 |
| `backups/` | 完整备份；本次升级前备份保留，历史备份按下方规则清理 |
| `releases/` | 升级版本的内部文件副本，用于重建镜像；当前版本必须保留 |

不要通过删除 `config/` 或 `data/` 解决安装报错。丢失微信加密密钥会导致已保存的 AppSecret 无法解密。

### 手动清理历史文件

历史版本、旧备份和旧镜像不会定时自动删除。在原网站目录先预览：

```bash
bash starlit.sh cleanup
```

确认清单后执行：

```bash
bash starlit.sh cleanup --apply
```

输入 `CLEAN` 才删除。保留当前版本、可识别的上一版本、最近两次完整备份及其依赖源码和镜像。无法确认归属、备份不完整或含额外文件时保留；其他容器正在使用的镜像也保留。不会执行全局 Docker prune。

首次安装后如需清理上传包和校验文件，先预览：

```bash
bash starlit.sh cleanup --downloads
```

确认后执行并输入 `CLEAN`：

```bash
bash starlit.sh cleanup --downloads --apply
```

这个清单也可能包含上述历史文件，请先阅读预览。

## 8. 常见问题

出现报错先保留终端输出，不要删除数据或重新安装。

| 情况 | 处理方式 |
| --- | --- |
| SHA256 校验失败 | 停止解压和安装，重新下载并上传压缩包及对应校验文件 |
| 镜像或 npm 下载超时 | 检查服务器 DNS 和出站网络；源码包需要能访问镜像仓库及 npm，镜像包省去现场构建，但首次安装 Docker、HTTPS 和微信仍需要联网 |
| 容器健康，但 HTTPS 检查失败或提示 OpenSSL 错误 | 检查域名 A/AAAA 记录、TCP 80/443、公网访问和网关日志；证书尚未签发时可能短暂失败，不能据此判定安装成功；按日志处理后再启动 |
| 域名显示服务商拦截页面 | 到服务商控制台检查域名接入状态；开放端口或重启应用不能解决域名拦截 |
| 数据库 unhealthy、Permission denied | 先看日志。新版脚本会将数据库挂载根目录设为 `999:999`、`0700`，仅重建异常数据库容器一次并保留数据；恢复失败会停止，不要删除数据库或改成 `777` |
| 微信校验文件无法访问 | 确认文件通过后台上传，域名公网可达，且返回的是原文件内容；目录由 API 写入、网关只读，默认 API 用户为 `1000:1000` |
| 升级失败 | 保留原网站目录、新包和备份，先排查日志；迁移失败不会自动回滚数据库，需要时按第 6 部分恢复 |

排查后重新启动会短暂中断网站，应避开活动时间。安装及升级完成后，请实际检查登录、上传图片、彩排抽奖、名单导出、微信签到及重启后的数据保留。
