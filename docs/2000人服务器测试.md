# 2000 人彩排数据：服务器测试步骤

适用于当前源码构建的部署包。新活动默认空彩排名单，支持按需生成不同头像的模拟参与者、每轮最多 10 人及头像本机缓存。

## 1. 安装或升级服务器

先按包内 INSTALLATION.md 完成安装或升级，确认网站可以登录。旧网站升级保留配置和业务数据；不要新建数据库或覆盖原网站目录。升级会短暂停止服务，请避开活动时间。

## 2. 生成 2000 名模拟参与者

1. 登录后台，创建一个专门用于测试的活动。
2. 保持彩排模式，进入「模式切换 → 模拟参与者」。
3. 在「模拟参与者总数」填写 **2000**，点击「生成模拟参与者」。
4. 新活动从空名单生成 2000 人；旧活动若已有 100 名模拟参与者，则只补充 1900 人。
5. 查看成功提示及当前模拟人数，再到「签到名单 → 彩排名单」检查总人数。

可填 1–5000 的整数。重复填写同一个目标不会继续累加；不会删除已有人员、覆盖排除资格或重置中奖结果。若已有其他彩排签到人员，总签到人数可能大于 2000。

每个模拟编号对应一张不同的 256×256 WebP 合成人物头像，最多 5000 张，无需外部图片服务。点击生成参与者后，服务器在后台按目标人数生成头像，最多同时编码两张；已生成的直接复用。首次进入大屏时可能仍在准备，按 H 查看进度。

生成文件保存到服务器运行目录的 `data/uploads/simulation/portraits-v1/`，本地开发默认是 `.local/uploads/simulation/portraits-v1/`（自定义 `ASSET_DIRECTORY` 时以其为准）。不同活动共享同编号的合成头像，不重复存储；删除活动不会删除这些可复用图片。源码仓库只保留生成代码，不附带这 5000 张图片。升级前已有的头像地址保持兼容，缺少缓存时按需补生成。已发布的历史部署包不受此次源码修改影响。

抽奖进行中、活动到期或已经启用正式模式时，不能生成模拟参与者。不要在活动进行中边抽奖边批量造数据。

如需减少人数，在「模式切换 → 清空彩排数据」清空后重新生成。此操作也会删除该场彩排的真实签到人员及抽奖记录，所以推荐使用专门的测试活动。只想重新抽奖则在中奖名单使用「清空抽奖」，保留已有参与者。

## 3. 检查完整业务流程

| 检查项 | 操作与预期 |
| --- | --- |
| 签到名单 | 显示 2000 人，翻页正常，搜索“模拟用户 2000”可找到完整编号 |
| Excel | 导出彩排名单，包含 2000 条人员记录（不含表头） |
| 大屏人数 | 进入彩排大屏，已签到人数与后台一致 |
| 头像轮换 | 同时显示的盒子数量保持各主题原设置，其他参与者通过轮换出现 |
| 真实抽奖池 | 未排除、未中奖的初始 2000 人均参与随机奖项的候选筛选，不限于当前显示的头像 |
| 多轮抽取 | 每轮最多 10 人，连续执行数轮，检查人数、剩余名额和名单保存 |
| 补抽 | 将一名中奖者标为不在场，执行补抽，确认作废与替代记录正确 |
| 清空抽奖 | 清空后大屏进度恢复，2000 人名单仍保留 |
| 清空彩排 | 清空后名单与抽奖记录为空，再次生成 2000 人正常 |
| 正式隔离 | 正式名单仍为空；模拟人员不会被复制到正式模式 |

在正式现场使用的电脑上分别检查梦幻星球、星光矩阵、星轨光波、星光长廊和星河瀑布。头像轮换需要时间，不会将 2000 个盒子一次性全部显示。

## 4. 记录服务器和浏览器表现

在服务器终端执行以下命令，分别记录待机、名单导出、开始/停止抽奖时的数据：

```bash
sudo docker stats --no-stream
free -h
df -h /opt
sudo bash starlit.sh status
sudo bash starlit.sh logs
```

连续观察时运行 `sudo docker stats`，按 Ctrl+C 结束观察。另记下：

- 服务器 CPU、内存与操作系统版本。
- 生成 2000 人、名单查询、导出和停止抽奖各耗时多久。
- 是否发生错误、超时、容器重启或内存持续增长。
- 现场电脑型号、浏览器、屏幕分辨率与各主题的流畅程度。

服务器 CPU 低不代表现场大屏一定流畅；3D 动画主要使用观众现场电脑的浏览器和显卡。

## 5. 这次测试覆盖什么

本功能生成的是实际保存到数据库的 2000 条彩排参与者记录，可检查名单、导出、抽奖、大屏数据和头像轮换。

**这不等于 2000 台手机同时扫码签到。** 新版使用 2000 张内容不同的合成头像，能够检查图片下载、解码、缓存和渲染；图片不是实际参与者的微信照片，不覆盖微信授权或集中签到请求。活动总人数也不等于瞬时并发人数，并发测试应按分批到场的扫码节奏单独设计，不能依据本次结果宣布服务器具备某一并发容量。

本地隔离 PostgreSQL/API 已测试 2000 条记录、完整 Excel 导出、2000 人抽奖池、权限与模式隔离；生产服务器表现以实际部署后的记录为准。
