# 星遇：Ubuntu / Debian 一键部署

> 本版包含手机签到品牌展示、中奖卡片排版、星河瀑布首次加载优化，以及部署维护改进。已有安装请走升级流程，保留原有配置和数据。

当前版本：**1.0.0-rc.1**（2026-10-22 重新编号，包含此前功能）。升级成功后自动清理本次上传文件和解压目录；从旧版升级时先按 INSTALLATION.md 更新维护脚本。镜像标签包含源码内容标识，避免复用早期同名 rc.1 镜像。新手请先阅读安装包根目录 `INSTALLATION.md`（源码仓库为 `docs/部署流程步骤.md`）：从上传工具、连接服务器开始，先讲首次安装，再讲升级。本文件用于查阅进阶部署和故障处理细节。

支持「模式切换 → 模拟参与者」，可补足到 1–5000 人，默认输入 2000。新活动默认不生成模拟人员；升级后已有人员保留。2000 人服务器测试步骤见包内 `TESTING.md`。

本包将网站、API、数据库和 HTTPS 网关一起部署。无需手动安装 Node.js、PostgreSQL、Nginx，也不需要 WSL 或 Docker Desktop。

**当前为候选版本：已提供安装、维护及打包工具。真实 Linux 容器启动、证书签发和真实微信扫码仍需服务器验收，不能将本地脚本测试等同于生产验收。**

## 先准备什么

1. 一台 Linux **x86_64 / amd64** 服务器和 root/sudo 权限，推荐全新服务器。暂未提供 ARM 包。
2. 一个解析到服务器公网 IP 的实际域名；若设置了 AAAA 记录，IPv6 也必须能访问此服务器。
3. 云安全组和主机网络允许入站 TCP **80、443**；443/UDP 为可选的 HTTP/3。保留自己的 SSH 管理端口，不要对外开放数据库端口。
4. 服务器可以访问 Docker 镜像仓库、npm 和证书服务。源码包首次安装需要联网构建；预构建镜像包可免去 npm 下载和构建，但 HTTPS 与微信仍需网络。

可先用 2 核、4GB 内存和 30GB 可用磁盘作为小规模试用起点；这不是并发容量承诺。源码构建、图片和备份会占用额外空间。大屏 3D 动画主要由现场电脑浏览器渲染，仍需现场测试。

### Linux 系统支持

- 本版部署目标为 **Ubuntu 22.04 / 24.04 LTS、Debian 12 / 13，x86_64 架构**；首轮服务器验收选 Ubuntu 24.04 LTS。
- 安装前核对发行版、版本和代号；不符合时会在安装系统软件前退出。暂不包含其他发行版、衍生发行版和 ARM 的自动安装。
- 自动通过 Docker 官方 apt 软件源安装 Docker Engine 和 Compose 插件，无需预装 Node.js、数据库或网站面板。各目标系统仍需真实服务器验证。
- 已有 Docker 时不会自动卸载或升级；已有容器运行时冲突、80/443 被占用时会中止，不会关闭原有网站。

依据：[Docker Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/)、[Debian 安装说明](https://docs.docker.com/engine/install/debian/)。Docker 发布端口的防火墙行为与普通主机进程不同，应同时检查云安全组，参见上述官方说明。

## 安装

上传并解压收到的 `starlit-版本-source.tar.gz` 或 `starlit-版本-images.tar.gz`，进入解压后的目录，然后运行：

```bash
sudo bash install.sh
```

根据提示输入：

1. 网站域名，例如 `lottery.company.cn`，不带 `https://`。
2. 首次登录账号、密码和确认密码。密码输入时不回显。

程序自动检查环境、安装所需工具、生成数据库密码和加密密钥、构建或导入镜像、迁移数据库、初始化账号并启动网站。最后会检查 HTTPS；只有通过才提示网站已启动。中途失败时保留配置与数据，处理提示后可重试同一命令，**不要删除 config/data 来重试**。

源码版第一次构建可能需要较长时间。镜像下载失败通常与服务器网络有关；不要使用来历不明的镜像或替换数据库版本来绕过错误。

首次启动前可执行 `sha256sum -c SHA256SUMS` 验证包内文件完整性。校验和用于发现损坏，不能代替可信的下载来源。

### 镜像下载时提示 connection refused / timeout

这表示构建机到镜像仓库的连接失败，需检查服务器的 DNS、出站网络及 Docker 代理配置。网站域名解析正常，不代表 Docker Hub 也能访问。

本项目使用 BuildKit 内置的 Dockerfile 解析器，不再额外下载 `docker/dockerfile:1`。旧 rc.2 包若在此镜像处失败，可在已生成 config 的安装目录执行下面命令去除该指令；仍需确保 Node、Caddy 和 PostgreSQL 镜像可以下载：

```bash
sudo sed -i '/^# syntax=docker\/dockerfile:1\r\?$/d' source/deploy/container/Dockerfile
getent ahostsv4 registry-1.docker.io
curl -I --connect-timeout 10 --max-time 15 https://registry-1.docker.io/v2/
```

收到 HTTP 401 表示此接口可达且要求认证，不等于所有镜像已可下载；超时或连接拒绝则应先解决网络问题。不要通过删除 config/data 重装，也不要关闭 TLS 校验。受限网络下可使用自有可信镜像仓库，或在可联网构建机制作含镜像的包；当前源码包不包含这些镜像。Dockerfile 指令行为参见 [Docker 官方说明](https://docs.docker.com/build/buildkit/frontend/)。

### 镜像来源与旧容器恢复

Node、Caddy、PostgreSQL 默认统一使用 `public.ecr.aws/docker/library/` 下的固定版本，不依赖 Docker Hub；这是 Docker Official Images 的 ECR Public 分发地址，参见 [Docker 官方发布说明](https://www.docker.com/press-release/docker-official-images-available-amazon-elastic-container-registry/)。服务器仍需要能访问 ECR Public、Docker 安装源和 npm，并非离线安装。安装包没有携带预构建镜像。

安装或 start 会修正数据库挂载根目录所有者；发现已有 db 容器处于 unhealthy 时，只重建该容器一次并保留原数据库。恢复失败会停止，不会删除数据或无限重试。

域名解析须在实际 NS 服务商处配置。中国内地云服务器还需满足服务商备案接入要求；备案拦截不由部署包修复。详见逐步操作流程。

## 微信配置

网站启动后，在后台「签到设置 → 微信服务号」配置自己的已认证服务号，按接入步骤完成微信侧的网页授权域名设置。

在「签到设置 → 配置服务号」点击「上传微信校验文件」，选择微信下载的原文件。系统保存到部署目录的 `data/verification/`，例如：

```text
data/verification/MP_verify_XXXXXXXX.txt
```

网站会在同名根路径提供该文件。不要把 AppSecret 放在此公开目录。生产环境不提供模拟微信授权；服务号未配置时不能完成真实微信签到。账号登录本身不依赖短信或微信。

回到「配置服务号」，确认校验文件名，勾选「已在微信后台保存上述网页授权域名」，点击「检查微信接入」。系统通过配置的 HTTPS 域名读取文件，与服务器原文件比对；通过后显示「微信接入已就绪」，模式切换同步放行，无需先扫码签到。此检查不会代替微信后台保存域名，也不代表已取得参与者授权。

仅有一个校验文件时会自动填入文件名；有多个文件时请选择本服务号对应的文件名填写。配置变更、域名变更或原文件被替换/删除后须重新检查。部署包将校验目录以读写方式挂载给 API（UID/GID 1000:1000），网关只读；自定义部署可用 `WECHAT_VERIFICATION_DIRECTORY` 指定同一个目录，默认 `/var/lib/starlit/verification`，并保证 API 服务账号可读写、网关账号可读。

## 常用维护

PostgreSQL 数据目录的挂载根目录 `data/postgres` 使用镜像内 postgres 用户的 UID/GID `999:999`，权限为 `0700`。安装、重新启动及恢复都会保持此设置。旧 rc.2 安装脚本将该目录设为 root 所有、`0700`，会阻止镜像切换到数据库用户后访问子目录；需要修正安装脚本与维护脚本的目录创建命令，不能只临时修改权限后再运行旧脚本。此修复保留数据库内容，不需要删除目录或放宽为 `777`。

在部署目录执行：

```bash
sudo bash starlit.sh status           # 查看容器状态
sudo bash starlit.sh logs             # 最近的数据库、应用及 HTTPS 日志
sudo bash starlit.sh stop             # 停止服务，保留数据
sudo bash starlit.sh start            # 启动或重试安装
sudo bash starlit.sh reset-password   # 重置指定账号密码
sudo bash starlit.sh backup           # 备份
sudo bash starlit.sh cleanup          # 只预览可清理对象
sudo bash starlit.sh cleanup --apply  # 预览后输入 CLEAN 确认删除
```

`start` 会重新创建网站容器，短暂中断访问，请避开正在进行的抽奖。不要同时运行多个维护命令。

### 哪些目录必须保留

| 目录 | 内容 |
| --- | --- |
| config | 数据库密码、登录签名密钥、微信加密密钥及域名 |
| data/postgres | PostgreSQL 数据 |
| data/uploads | 上传图片与缓存头像 |
| data/caddy、data/caddy-config | HTTPS 证书及网关状态 |
| data/verification | 微信域名校验文件 |
| backups | 数据库、图片、配置和证书的备份 |
| releases | 升级版本的安装文件，供后续重建镜像使用 |

**不要重新生成 config 密钥或删除 data。** 丢失微信加密密钥后，已有 AppSecret 无法解密。普通升级不覆盖这些目录。

## 备份与恢复

备份会短暂停止网站写入，使用 `pg_dump` 保存数据库并复制图片、配置与证书。正常完成或备份失败时，都会尝试恢复备份前正在运行的网站。输出的备份目录带有校验清单；含 `INCOMPLETE` 的备份不能恢复。

备份包含敏感密钥，需要加密保存或使用受控存储，并复制到服务器之外。仅放在原服务器上不能防止整机损坏。目前提供手动备份命令，尚未启用定时备份。

恢复仅允许在**全新的部署目录**执行，使用与备份相同版本的包；不覆盖已有安装。建议用另一台服务器演练恢复：

```bash
# 新服务器先安装 Docker Engine、Compose 和 curl 等工具；不要先运行 install.sh 创建新库。
sudo bash engine.sh
sudo bash starlit.sh restore /绝对路径/完整备份目录
```

恢复时保留原域名和密钥。切换服务器后更新域名解析、微信服务器 IP 白名单，并重新验证 HTTPS 和手机签到。如果本机还存在原项目容器，恢复会拒绝，避免连接到原项目。恢复中途失败会留下现场供排查；不要把不完整目标当成成功恢复。

## 升级

先按 INSTALLATION.md 完成上传、校验、解压和维护脚本更新。新包须位于**旧部署目录以外的另一目录**，不要在新目录执行安装。以下是进阶命令格式；从旧版首次使用自动清理时，不能省略 INSTALLATION.md 中更新维护脚本的步骤。在旧部署目录运行：

```bash
sudo bash starlit.sh upgrade /绝对路径/新版本部署目录
```

工具先准备新镜像，再暂停网站、做完整备份、执行迁移并重新创建网站容器。升级会中断访问，请避开活动时间。版本升级不使用 `latest`。本次按用户要求重新从 rc.1 编号，旧同名目录不可覆盖；此后每次发布继续使用新的版本号，不能重复发布不同内容。镜像标签含源码内容标识，防止复用早期同名镜像。

数据库迁移失败时保持网站停止，避免旧程序使用半升级状态。**不会自动降级数据库**；保留错误现场，使用旧版本包和升级前备份恢复到新目录或另一台服务器。数据库大版本升级不在此命令范围内（本版固定 PostgreSQL 18）。

## 给项目发布者

在源码项目中运行：

```bash
npm run package:deploy -- --version=1.0.0-rc.1
```

生成仅含白名单源码的安装包，不携带本地数据库、上传图片、`.env`、登录凭据或 Windows node_modules。

该命令先执行类型检查、单元测试、生产构建、部署脚本测试，以及数据库迁移、开场检查、抽奖、签到、实时同步和微信生命周期回归。任一步失败都停止打包；验收或打包期间源码变化也会停止。需先安装项目依赖和测试用 Chrome（可通过 `CHROME_PATH` 指定路径）。

仅验收、不生成部署包：`npm run release:check`。成功记录在 `artifacts/release-check-*/verification.json`。部署包内的 `RELEASE.json` 记录版本、构建时间、源码与测试输入指纹、包内容指纹及通过的检查。SHA256 文件用于校验压缩包完整性，两者用途不同。

每次发布必须显式指定新版本号。同一工作区已成功发布的版本记录在 `artifacts/releases/`，不得重复使用；跨构建机发布也应统一管理版本号。中断后如果遗留 `artifacts/.release.lock`，先确认发布进程已结束，再移除该锁文件重试。验收使用隔离测试数据库；真实服务器的安装、HTTPS 和真实微信授权仍需下方现场验收。

在有 Docker Engine 的构建机上，可生成含 Linux amd64 镜像的包：

```bash
npm run package:deploy -- --images --version=1.0.0-rc.1
```

镜像包更适合交付最终用户，首次安装无需现场编译。该命令不会发布到公网仓库。对外正式发布前必须在真实 Linux 上完成下列验收：

- 全新安装、初始化账号、登录、重启服务器后自动恢复。
- HTTPS 证书签发，三个网页入口，上传图片、Excel 导出、大屏与后台实时同步。
- 创建活动、彩排/正式隔离、开奖、补抽和清空记录。
- 备份后恢复到另一台服务器，核对账号、图片、微信密钥和抽奖记录。
- 旧版本升级、迁移失败中止、从升级前备份恢复。
- 真实微信授权、首次签到、重复扫码和无字段自动签到。

清理保留规则及显式清理下载包的方法见 CLEANUP.md（源码中为 docs/升级后清理.md）。
